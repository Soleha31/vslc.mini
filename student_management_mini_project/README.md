# Student Management System

A beginner-friendly mini project demonstrating Flask, Git/GitHub, Docker, and Render cloud deployment.

## Features
- Add, list, search, edit, and delete student records
- SQLAlchemy database layer
- SQLite by default for local development
- PostgreSQL when `DATABASE_URL` is configured
- `/health` endpoint for deployment health checks

## 1. Run locally on Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000

If PowerShell blocks activation, run this in the same terminal:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

## 2. Test the health endpoint
Open http://127.0.0.1:5000/health. Expected JSON includes `"status":"ok"`.

## 3. Git and GitHub

Create an empty GitHub repository named `student-management-system` (do not initialize it with a README if you follow these commands).

```powershell
git init
git add .
git commit -m "Initial Student Management System"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/student-management-system.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your GitHub username. GitHub may ask you to sign in through a browser.

## 4. Run with Docker

Install and start Docker Desktop first, then open a new PowerShell terminal in this project folder.

```powershell
docker build -t student-management-system .
docker run --name student-management-app -p 5000:10000 -e PORT=10000 student-management-system
```

Open http://127.0.0.1:5000. Stop the container with Ctrl+C, then in another terminal remove it if needed:
```powershell
docker rm -f student-management-app
```

## 5. Deploy on Render using Docker

1. Push the project to GitHub.
2. Sign in at https://dashboard.render.com/
3. Choose **New + → Blueprint** and select your GitHub repository containing `render.yaml`.
4. Review the services and database described by the Blueprint. The database plan may incur charges; review the current price before confirming. If you do not want to create a paid database, deploy only the web service and configure a database separately.
5. If deploying manually instead: choose **New + → Web Service**, connect the repository, set Runtime/Language to **Docker**, and ensure the Dockerfile is in the repository root.
6. Set `SECRET_KEY` to a strong random value in the Render environment settings if not generated by the Blueprint.
7. For persistent student records, configure `DATABASE_URL` to a managed PostgreSQL database. Do not rely on container-local SQLite for persistent cloud data.
8. Wait for the deploy to succeed, then open the `onrender.com` URL shown in the dashboard.
9. Test the home page and `/health`.

Render documentation:
- https://render.com/docs/docker
- https://render.com/docs/web-services
- https://render.com/docs/configure-environment-variables

## Important
- Never commit `.env`, passwords, or database credentials.
- Use fictional student data for demonstrations.
- This starter is for an academic mini project. Add authentication, CSRF protection, stronger validation, migrations, and backups before real-world use.
